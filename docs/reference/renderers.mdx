title: Renderer comparison
description: Compare the React Native, React DOM, and experimental Solid 2 renderers.
---

super-calendar provides three renderers over one shared core (`@super-calendar/core`):

- **`@super-calendar/native`** uses React Native (iOS, Android, and web via
  react-native-web). The reference renderer; gesture-driven and virtualized.
- **`@super-calendar/dom`** uses plain react-dom, for web-only or web-first apps that
  don't want to pull in React Native.
- **`@super-calendar/solid`** provides experimental Solid 2 web components and
  imports the React-free `@super-calendar/core/vanilla` entry.

The renderers share calendar views and core types. The tables compare their
components, interactions, and styling. Solid support is experimental.

## Solid 2 differences

Solid uses `JSX.Element` from `@solidjs/web` for render callbacks, `createDateRange`,
`createMonthGrid`, `createNow`, and `createEventSource` for reactive state, and `SolidCalendarTheme`
with `defaultSolidTheme` and `darkSolidTheme` for styling. Component prop names
match React DOM, including `className`, `classNames`, and `styles`.

`MonthList` and `Agenda` use measured row virtualization without Legend List.
The package is ESM and supports server rendering and hydration. It targets exact
Solid 2 release-candidate peers and uses the `experimental` npm tag. See the
[Solid 2 guide](/guides/solid) for installation and compiler settings.

## Views and components

| Component / view                      | React Native | React DOM | Solid 2 | Notes                                                       |
| ------------------------------------- | :----------: | :-------: | :-----: | ----------------------------------------------------------- |
| Month, week, day, 3-day, custom, year |      ✅      |    ✅     |   ✅    | The same `Calendar` modes.                                  |
| Schedule / agenda                     |      ✅      |    ✅     |   ✅    | `mode="schedule"`.                                          |
| `TimeGrid`, `MonthView`, `MonthList`  |      ✅      |    ✅     |   ✅    | Shared components, matching prop names.                     |
| `Agenda`, `ResourceTimeline`          |      ✅      |    ✅     |   ✅    |                                                             |
| `MonthPager` (paged month swipe)      |      ✅      |    ❌     |   ❌    | Web `Calendar` shows one window; use `MonthList` to scroll. |
| `DatePicker` / `DateRangePicker`      |      ❌      |    ✅     |   ✅    | Native exposes headless picker parts through `/picker`.     |

## Interaction

| Capability                     | React Native | React DOM | Solid 2 | Notes                                                                             |
| ------------------------------ | :----------: | :-------: | :-----: | --------------------------------------------------------------------------------- |
| Drag to move / resize / create |      ✅      |    ✅     |   ✅    | Native uses long-press gestures. Web uses mouse, touch, or pen pointers.          |
| Month drag (create / move day) |      ✅      |    ✅     |   ✅    | Sweep an all-day span, or drop an event on another day. Resize is time-grid only. |
| Year drag (select / create)    |      ✅      |    ✅     |   ✅    | Native keeps a sweep inside the month it started in.                              |
| Pinch / scroll to zoom         |      ✅      |    ✅     |   ✅    | Native uses pinch. Web also supports Ctrl/⌘-scroll with `zoomable`.               |
| Controlled navigation          |      ✅      |    ✅     |   ✅    | `onChangeDate`: native swipe/paging, web PageDown/PageUp on the focused grid.     |
| RTL layout                     |      ✅      |    ❌     |   ❌    | Native `isRTL` is cosmetic.                                                       |
| Respects OS reduce-motion      |      ✅      |    ✅     |   ✅    | Native disables page-snap animation. Web renderers use almost no animation.       |

## Data

| Feature                                 | React Native | React DOM | Solid 2 | Notes                                                         |
| --------------------------------------- | :----------: | :-------: | :-----: | ------------------------------------------------------------- |
| Recurrence auto-expansion in `Calendar` |      ✅      |    ✅     |   ✅    | Also `expandRecurringEvents` for manual control.              |
| `timeZone` prop                         |      ✅      |    ✅     |   ✅    | Display-only, via `eventsInTimeZone`.                         |
| iCalendar import / export               |      ✅      |    ✅     |   ✅    | `parseICalendar` / `toICalendar`, exported by every renderer. |

## Styling and accessibility

| Feature                        | React Native | React DOM | Solid 2 | Notes                                                                                                                      |
| ------------------------------ | :----------: | :-------: | :-----: | -------------------------------------------------------------------------------------------------------------------------- |
| Theming                        |      ✅      |    ✅     |   ✅    | `CalendarTheme`, `DomCalendarTheme`, or `SolidCalendarTheme`, respectively.                                                |
| Per-slot `classNames`/`styles` |      ✅      |    ✅     |   ✅    | A classed slot drops its themed styles. Native needs a Tailwind runtime; web supports CSS. See [Styling](/guides/styling). |
| Screen-reader labels and roles |      ✅      |    ✅     |   ✅    | Events, month cells, and day headers are labelled.                                                                         |
| Move / resize without dragging |      ✅      |    ✅     |   ✅    | Native exposes `accessibilityActions` for VoiceOver/TalkBack. Web provides an event chooser and an actions dialog.         |
| Keyboard navigation            |      ❌      |    ✅     |   ✅    | Web supports `keyboardDayNavigation` and `keyboardEventNavigation`. Native supports arrow-key paging on react-native-web.  |

<Note>
  The shared components (`MonthView`, `MonthList`, `TimeGrid`) keep the same prop names across
  renderers, guarded by an automated parity test. A genuinely platform-specific prop (web keyboard
  nav, RN styling) is the only allowed exception.
</Note>
