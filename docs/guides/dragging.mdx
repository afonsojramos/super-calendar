Everything here is opt-in: pass the relevant handler and update your own event
state in response. Move, resize, and create work on the week/day grid; move and
create also work on the month grid (see [On the month grid](#on-the-month-grid)),
where a drag moves an event by whole days rather than by time. The year grid
sweeps out day ranges too (see [On the year grid](#on-the-year-grid)).

## Move and resize

Pass `onDragEvent` to make events draggable. Move an event (**long-press** it on
native, **click-drag** it on web), or **drag the grip** at its **bottom edge to
change the end** or its **top edge to change the start**. Drag **vertically to
change the time, horizontally to move it to another day** (within the visible
range). New `start`/`end` are snapped to `dragStepMinutes` (default 15).

```tsx
<Calendar
  /* ... */
  onDragEvent={(event, start, end) =>
    setEvents((prev) => prev.map((e) => (e.id === event.id ? { ...e, start, end } : e)))
  }
/>
```

### DOM held presses

On the DOM time grid, touch and pen wait for a 300 ms hold within 8 px before
dragging. A tap calls `onPressEvent` from the event's own click. A vertical swipe
that starts on an event or resize grip scrolls the grid. During a held drag,
scrolling stops until release or cancellation. Mouse dragging starts immediately.

Set `touchDragDelay` (milliseconds) and `touchDragThreshold` (pixels) on DOM
`Calendar` or `TimeGrid` to adjust the hold. Movement, pointer cancellation,
another finger, navigation, or unmount cancels a pending hold.
An additional contact on an event or resize grip cannot start a replacement hold
or take over an active drag.
These options apply to event gestures, not empty-slot or month interactions.

In the multi-week web grid, keep the `events` input stable when `onDragStart`
updates unrelated UI state. With recurrence or `timeZone`, a new array rebuilds
the displayed events and cancels a held move. See
[keep event data stable](/guides/events#keep-event-data-stable).

### Move an event past midnight

A move keeps its duration, so dragging an event **down past the end of the day**
lets its end run into the next one: the box cuts off at the day boundary and the
remainder previews at the top of the next column, exactly where the committed
event will render. The **start** stays in the day you dropped it on (it stops one
`dragStepMinutes` step before the end of the day), so a move to a different day is
still the horizontal drag.

`onDragEvent` then receives a `start` and `end` on different dates. Dragging any
day's segment of the resulting multi-day event moves the whole thing, so it never
gets clipped to the day you grabbed. All visible segments preview the move together,
including segments that enter a new column. Both dates shift together to preserve
the event's duration. For example, moving a Tuesday 17:00 to Thursday 21:00 event
one day earlier previews Monday 17:00 to Wednesday 21:00, whichever segment you grab.
Use a resize grip to change just the start or end.

### Hide the drag handle

By default a small grip shows at each draggable event's bottom edge. Set
`showDragHandle={false}` to hide that indicator while keeping drag-to-move and
drag-to-resize fully working, so events stay editable without the visual marker.
You can toggle `showDragHandle` after mounting; native time-grid grips update
without replacing the `events` array.

```tsx
<Calendar
  /* ... */
  showDragHandle={false}
  onDragEvent={(event, start, end) =>
    setEvents((prev) => prev.map((e) => (e.id === event.id ? { ...e, start, end } : e)))
  }
/>
```

### Colour an event's grips

Set `dragHandleColor` on an event to override its resize grip colour in
`@super-calendar/native`. This applies to both time-grid grips and to the
resource timeline's grip in either orientation. Omit it to use
`theme.colors.eventText`. Choose a colour that contrasts with the event's background.

```tsx
import type { CalendarEvent } from "@super-calendar/native";

const events: CalendarEvent[] = [
  {
    title: "Blocked time",
    start: new Date(2026, 5, 23, 9),
    end: new Date(2026, 5, 23, 10),
    dragHandleColor: "#ffffff",
  },
];
```

`showDragHandle={false}` still hides the time-grid grips. The DOM renderer's
resize targets have no visible grips, so this field does not change their appearance.

### Lock specific events

`onDragEvent` makes **every** event draggable, which is the right default: most
calendars let you reschedule anything. When a few events must never move (a
confirmed booking, an event someone else owns, a holiday), set `draggable: false`
on those events. They keep their normal appearance and still respond to taps, they
just can't be picked up or resized. Nothing else needs to change.

```tsx
const events = [
  { id: "1", title: "Standup", start, end },
  { id: "2", title: "Driving test", start, end, draggable: false }, // can't be moved
];
```

Reach for this when an event can _never_ move, so you don't offer a drag that only
snaps back. To refuse a move for some targets but not others (see below), keep the
event draggable and reject the specific drop instead. (For an event that shouldn't
respond to taps either and should read as unavailable, use `disabled: true`, which
also dims it.)

### Allow only move or only resize

Split the two with `startEditable` (can be moved) and `durationEditable` (can be
resized), per event or grid-wide via `eventStartEditable` / `eventDurationEditable`
(both default `true`). A `draggable: false` event stays fully locked regardless.

```tsx
const events = [
  { id: "1", title: "Standup", start, end, durationEditable: false }, // move, don't resize
  { id: "2", title: "Focus", start, end, startEditable: false }, // resize, don't move
];

// Or a grid-wide default (e.g. resize is off everywhere):
<Calendar eventDurationEditable={false} onDragEvent={onDrag} /* ... */ />;
```

### Reject a drop

Return `false` from `onDragEvent` to refuse a particular placement — the event
snaps back to where it started (on the time grid a cross-week drop snaps the view
back too, so the rejection is visible). Use it for rules that depend on where the
event lands: overlaps, out-of-bounds slots, or business-hours limits. The library
is expo-free, so fire your own feedback (a haptic, a toast) right where you reject.

```tsx
import * as Haptics from "expo-haptics";

onDragEvent={(event, start, end) => {
  if (overlapsAnother(event, start, end)) {
    void Haptics.notificationAsync(Haptics.NotificationFeedbackType.Error);
    return false;
  }
  setEvents((prev) => prev.map((e) => (e.id === event.id ? { ...e, start, end } : e)));
}}
```

The overlap case is common enough that it's built in: set `eventOverlap={false}` and
the grid rejects any drag or resize that would land an event on top of another,
without you checking in `onDragEvent`. For your own rules, `eventsOverlap` and
`overlapsOtherEvents` are exported from `@super-calendar/core`.

```tsx
<Calendar eventOverlap={false} onDragEvent={onDrag} /* ... */ />
```

### Haptics on grab

`onDragStart` fires the instant an event is picked up for a move or resize,
before anything is committed. The library is expo-free, so bring your own
haptics:

```tsx
import * as Haptics from "expo-haptics";

<Calendar
  /* ... */
  onDragStart={() => {
    void Haptics.impactAsync(Haptics.ImpactFeedbackStyle.Medium);
  }}
/>;
```

### Move an event to another week

While moving an event, drag it past the left or right edge of the day columns and
hold briefly. The view pages to the previous/next period and the event lifts into
a floating copy that keeps following your finger, so the drag stays live across the
page change and you drop it on any day of the newly revealed week. Both renderers
need `onChangeDate` set (they already do for paging); the page only advances on a
deliberate dwell at the very edge, so a normal in-view drag never trips it.

On native the pager's own swipe is frozen for the moment it pages, so the view
advances under your held finger instead of waiting for you to lift.

On native, the floating copy's horizontal centre selects the destination day.
Its top edge selects the time. This also applies to narrower boxes for overlapping
events, so a copy mostly over a day lands in that column even if its left edge
crosses the previous column.

In-view move, cross-day within the visible columns, and resize all work by gesture
as usual on both.

On the DOM time grid, only mouse drags trigger edge paging. Touch and pen drags
remain inside the visible period. A resting finger cannot repeatedly change the
date or detach its captured event through an edge page.

### Rescheduling without dragging

Dragging is a gesture, so every renderer offers the same moves and resizes
another way. They run through the same commit path as a drag, so `onDragEvent`
fires exactly as it would from a gesture (and can still return `false` to
reject). `eventOverlap={false}`, `draggable: false`, `startEditable`, and
`durationEditable` apply as they do to a drag.

On React DOM and Solid, choose **Edit events**, then an event, to open a dialog with **Move 15 minutes later /
earlier**, **Extend / Shorten by 15 minutes**, and **Move to next / previous
week** (per mode: the page span), stepping by `dragStepMinutes`. It works with a
keyboard, a click, or a tap, and never presses or drags the event itself.
Rejected edits show a polite status message, customizable with
`labels.eventChangeRejected`. Pass `getEventId` to retain the dialog's event
through full data refreshes. See
[Move and resize actions](/guides/accessibility#move-and-resize-actions-web).

On the React Native renderer draggable events also carry
**accessibility actions** for VoiceOver / TalkBack users: _move earlier_, _move
later_, (when the event owns its end) _extend_ / _shorten_, and _move to next /
previous week_ (per-mode: the page span), each stepping by `dragStepMinutes` or a
whole page. The built-in event renderer wires these up automatically; a custom
`renderEvent` should spread the `accessibilityActions` and `onAccessibilityAction`
it receives onto its pressable to keep the event operable by assistive tech.

## Drag to create

Pass `onCreateEvent` to sweep out a new event on empty grid space:
**long-press and drag** on native, **click-drag** on web. The handler receives
the snapped `start`/`end` on release (a stationary press yields a one-step
range). On native it supersedes `onLongPressCell`; on web, dragging empty space
creates instead of scrolling (use the wheel to scroll), and **Escape** cancels an
in-progress sweep before it commits.

React DOM and Solid `TimeGrid` complete creation on pointer release, including
when pointer capture is lost immediately before release. Capture loss without
a matching release or cancelling the pointer cancels the sweep without creating
an event. A new press discards a stale sweep left by a missed release outside
the window. While a mouse or pen sweep is active, text selection and native
browser dragging are disabled so they cannot interrupt creation.

```tsx
<Calendar
  /* ... */
  onCreateEvent={(start, end) =>
    setEvents((prev) => [...prev, { id: makeId(), title: "New event", start, end }])
  }
/>
```

<Note>
  A live ghost box previews the range as you sweep. Tap (no drag) on empty space still fires
  `onPressCell` with the pressed date+time, so you can support both "tap to create a point" and
  "drag to create a range."
</Note>

On the web, the time-grid preview snaps both ends to the range that
`onCreateEvent` receives, using `dragStepMinutes` or the default 15 minutes.
The initial press shows one snapped slot. Short previews use `minEventHeight`,
like committed events, with clipping at the visible-hour boundary taking
priority over that minimum. This also works without
`renderCreateGhost`. The preview stays inside the visible hours. When a sweep
passes the start or end of those hours (00:00 and 24:00 by default, or `minHour`
and `maxHour`), the preview stops at that edge. Its border and minimum height stay
inside the column, including borders from a `createGhost` class or style. The
preview uses the existing `onCreateEvent` range within the pressed day. For an
upward sweep whose origin rounds to midnight, that range ends one snap step
before midnight, and the preview ends there too.

### Show a draft in the preview

The preview is empty by default. To show a draft title or the live time range
inside it, pass a `renderCreateGhost` component. It receives `start` and `end`
as `Date`s: the snapped range `onCreateEvent` would receive if the sweep ended
at the pointer's current position. They are ordered, at least one
`dragStepMinutes` step long, and clamped to the pressed day, exactly as on
release. The component re-renders whenever the range changes, before
`onCreateEvent` fires.

```tsx
import { Calendar, type CreateGhostArgs } from "@super-calendar/dom";
import { format } from "date-fns";

function DraftPreview({ start, end }: CreateGhostArgs) {
  return (
    <div style={{ padding: "2px 6px", fontSize: 12 }}>
      <strong>New event</strong>
      <div>{`${format(start, "HH:mm")} - ${format(end, "HH:mm")}`}</div>
    </div>
  );
}

<Calendar
  mode="week"
  /* ... */
  onCreateEvent={(start, end) =>
    setEvents((prev) => [...prev, { id: makeId(), title: "New event", start, end }])
  }
  renderCreateGhost={DraftPreview}
/>;
```

On React Native, return `Text` (and views) instead of DOM elements:

```tsx
import { Calendar, type CreateGhostArgs } from "@super-calendar/native";
import { format } from "date-fns";
import { Text } from "react-native";

function DraftPreview({ start, end }: CreateGhostArgs) {
  return (
    <Text
      numberOfLines={2}
    >{`New event\n${format(start, "HH:mm")} - ${format(end, "HH:mm")}`}</Text>
  );
}

<Calendar mode="week" /* ... */ onCreateEvent={createEvent} renderCreateGhost={DraftPreview} />;
```

In Solid, read the props inside JSX instead of destructuring them, so the text
follows the sweep:

```tsx
import { Calendar, type CreateGhostArgs } from "@super-calendar/solid";
import { format } from "date-fns";

function DraftPreview(props: CreateGhostArgs) {
  return (
    <strong>{`New event ${format(props.start, "HH:mm")} - ${format(props.end, "HH:mm")}`}</strong>
  );
}

<Calendar mode="week" /* ... */ onCreateEvent={createEvent} renderCreateGhost={DraftPreview} />;
```

The calendar still positions, sizes, and styles the preview (including the
`createGhost` slot), and you own only its content. That content is clipped to
the preview box, ignores the pointer, and stays out of the tab order and the
accessibility tree, like the empty preview. Keep it visual: controls inside it
can't be reached.

A few rules apply:

- `renderCreateGhost` needs `onCreateEvent`. On its own it does not enable
  creation, and with only `onPressCell` the preview stays empty. Removing
  `onCreateEvent` cancels an active sweep.
- In React, define the component once outside render, as with `renderEvent`. A
  new inline function on every render remounts the content and drops its state.
- `Calendar` forwards it in the time-grid modes (`day`, `3days`, `week`,
  `custom`). For month and multi-week modes, see [Show a month draft](#show-a-month-draft).
  Year sweeps don't use it. `ResourceTimeline` accepts the
  same prop and adds the lane's `resource` to the props, in both orientations.
- The range can extend past a narrowed `minHour`/`maxHour` window. On the web
  the preview box stops at the visible edge, but `start` and `end` keep matching
  what `onCreateEvent` will receive, which is clamped to the pressed day, not
  to the visible hours.
- In React DOM and Solid, scrolling or zooming during a held sweep updates the
  preview range even if the pointer does not move again before release.
- The content clears when the sweep ends or is cancelled, and each new sweep
  mounts it fresh. Changing the pressed column to another day cancels the sweep.
  In React DOM and Solid, **Escape** cancels the sweep. Losing pointer capture
  also cancels it unless a time-grid sweep is released immediately afterward,
  and a press without a drag shows the one-step range while held, then fires
  `onPressCell` instead of creating. On React Native, a stationary hold creates
  that one-step range. A cancelled native gesture clears the preview without
  calling `onCreateEvent`.
- On React Native, the preview geometry stays on the UI thread. Pointer and
  zoom updates cross to JavaScript only when the snapped range changes.

## On the month grid

The same two handlers work in `month` mode on all three renderers. Nothing extra to
enable: pass `onCreateEvent`, `onDragEvent`, or both.

In React DOM and Solid month and multi-week grids, **Escape** or cancellation
of the active pointer ends a create or move gesture without calling its commit
handler. Release and cancellation events from other pointers do not end the active gesture.

### Drag to create a day span

Press an empty day and drag across others to sketch an **all-day** span, then
release. `start` is midnight of the first day and `end` is midnight after the last
(exclusive). On native you **long-press** first, so a tap and a page swipe are
never hijacked, and a stationary hold creates that single day; on web a plain
click without dragging creates nothing and still fires `onPressDay`.

```tsx
<Calendar
  mode="month"
  /* ... */
  onCreateEvent={(start, end) =>
    setEvents((prev) => [...prev, { id: makeId(), title: "New", start, end, allDay: true }])
  }
/>
```

`onSelectDrag` reports the **same sweep** as it happens, with the ordered inclusive
`[start, end]` days, so a selection highlight can follow the drag rather than
appearing only on release. Set it, `onCreateEvent`, or both; either enables the
gesture. See [Date selection](/guides/selection) for wiring it to `useDateRange`.

### Show a month draft

Pass `renderCreateGhost` to `MonthView`, `MultiWeekView`, or `Calendar` in
`month` or `multiweek` mode in any renderer.
It receives the full all-day `start` and exclusive `end` that `onCreateEvent`
would receive on release. Each week row crossed by the sweep renders one copy
with the same range, including when you drag backward.

<CodeGroup>

```tsx React DOM
import type { CreateGhostArgs } from "@super-calendar/dom";
import { format } from "date-fns";

function MonthDraft({ start, end }: CreateGhostArgs) {
  return <span>{`New: ${format(start, "MMM d")} to ${format(end, "MMM d")} (exclusive)`}</span>;
}
```

```tsx React Native
import { Calendar, type CreateGhostArgs } from "@super-calendar/native";
import { format } from "date-fns";
import { Text } from "react-native";

function MonthDraft({ start, end }: CreateGhostArgs) {
  return (
    <Text
      numberOfLines={1}
    >{`New: ${format(start, "MMM d")} to ${format(end, "MMM d")} (exclusive)`}</Text>
  );
}

<Calendar mode="month" /* ... */ onCreateEvent={createEvent} renderCreateGhost={MonthDraft} />;
```

```tsx Solid
import type { CreateGhostArgs } from "@super-calendar/solid";
import { format } from "date-fns";

function MonthDraft(props: CreateGhostArgs) {
  return (
    <span>{`New: ${format(props.start, "MMM d")} to ${format(props.end, "MMM d")} (exclusive)`}</span>
  );
}
```

</CodeGroup>

The preview uses `chipHeight`, `chipGap`, and the `createGhost` styling slot.
It occupies the next available visible lane, or overlays the last lane when
the row is full, without moving existing events. Its content is clipped,
ignores pointer input, and is hidden from screen readers. On web, it also stays out of the tab order. It updates as the
sweep reaches another day and clears on release or cancellation.

The renderer requires `onCreateEvent`. An empty month shows the event-grid
layout when both are set, so you can preview the first event. Without the
renderer, the existing day highlight and empty picker layout are unchanged.
In DOM and Solid, the event-grid layout disables arrow-key day navigation by
default. Set `keyboardDayNavigation` to keep it enabled before and after creating
the first event.

### Drag to reschedule

Pick an event bar up and drop it on another day. Both ends shift by the same
number of calendar days, so the **time of day and the duration are preserved**
(a multi-day event keeps its length). Grab it with a **long-press** on native and
a **press-drag** on web. The carried bar fades and the target day is tinted while
you drag. On web, a press becomes a drag only after the pointer travels a few
pixels, so clicking a movable bar fires `onPressEvent` rather than the day's
`onPressDay` or `onPressCell`.

```tsx
<Calendar
  mode="month"
  /* ... */
  onDragEvent={(event, start, end) =>
    setEvents((prev) => prev.map((e) => (e.id === event.id ? { ...e, start, end } : e)))
  }
/>
```

Everything above applies here too: `draggable: false` and `startEditable: false`
lock an event, `eventStartEditable={false}` locks the whole grid, returning
`false` rejects a drop, and `eventOverlap={false}` rejects one that would land on
top of another event. `onDragStart` fires on grab, for haptics. There is no resize
on the month grid, so `durationEditable` has no effect there.

### Styling the drag states

Both states are tinted with the theme's `rangeBackground` token by default (see
[Theming](/guides/theming)), and the bar being carried fades. On the dom renderer
each day in a create sweep also carries `data-creating` and the day an event is
about to land on carries `data-drop`, so you can restyle either (see
[Styling](/guides/styling)); give the `day` slot a class to take the tint over
entirely.

## On the year grid

The twelve mini months take the same sweep: `onSelectDrag` reports the ordered
inclusive `[start, end]` days as you drag, and `onCreateEvent` reports the
all-day range once on release. Hold a day and drag on a device, press and drag on
the web. Days being swept carry `data-creating` on the dom renderer.

```tsx
<Calendar
  mode="year"
  /* ... */
  selectedRange={range ?? undefined}
  onSelectDrag={selectRange}
  onCreateEvent={(start, end) =>
    setEvents((prev) => [...prev, { id: makeId(), title: "Leave", start, end, allDay: true }])
  }
/>
```

On a device a sweep stays inside the mini month it started in; on the web it can
carry on across months. The year view summarises events as dots rather than bars,
so it has nothing to pick up: `onDragEvent` applies to `month` mode, not `year`.

## Tuning the snap

`dragStepMinutes` (default 15) controls how move, resize, and create snap on the
week/day grid. The month and year grids always snap to whole days.
